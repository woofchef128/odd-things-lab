# 麻瓜研究所

这是手机版优先的手作商店，包含顾客页面和店长工作台。人类是麻瓜，小狗是连接店长与麻瓜的店员。

## 先看效果

打开 `magua-lab-complete.html` 可体验整版。它自带图片、字体和音效，可离线打开。

`magua-lab-netlify-preview.zip` 解压后，把里面的文件拖进 Netlify Drop 可分享互动样版。样版资料仅存在各自浏览器，适合看设计和试操作。

示例订单号码为 `49`，下单电话后四位为 `2049`。示例包含虚拟商品和金额，请勿按示例实际转账。

## 正式商店部署

正式版使用本项目代码和 PostgreSQL 数据库，订单、库存、留言、员工身份由服务端统一保存。

1. 把项目解压并放进 Git 仓库，从 Netlify 导入该仓库。
2. Netlify 使用根目录的 `netlify.toml`。发布目录为 `public`，函数目录为 `netlify/functions`，无需前端构建命令。使用 Node 22 或更新的兼容版本。
3. 在 Netlify 的环境变量中填写 `DATABASE_URL`、`ADMIN_PASSWORD`、`SESSION_SECRET`。数据库连接串应使用数据库服务提供的 TLS 连接配置。密码和密钥仅放服务端，`SESSION_SECRET` 用随机长字符串。
4. 部署后打开 `/#admin`，用店长密码登录。数据库会在首次访问时建立数据表，正式数据库初始为空。
5. 设置西马、东马及纳闽运费，上传真实商品和收款 QR，再开始接单。后台可保存商品名、分区、图片、价格、现货数量、预购时间、规格和是否上架。规格每行按 `1 位麻瓜 | 59` 填写。
6. 用一笔真实流程的测试订单核对订单、运费、图片和付款资料，再开放给顾客。

正式项目需要部署 Functions。将 `public` 单独拖到 Drop 不能提供共享数据库或店长身份验证。完整项目请通过 Git 导入，或用 Netlify CLI 从根目录部署。

## 顾客流程

首页有简版麻瓜日历、可重复丢的圣杯和三个插画入口。底部保留补给站、追踪局和麻瓜来信。

商品先显示三类图片入口，点击展开。3D 打印可以上架现货、预购或联系店长定制。粘土人偶与盲盒按预购设置，粘土可加不同人数规格，盲盒可上架不同系列。

购物车支持数量增减。付款入口先显示邮寄资料，下滑为付款。必填资料缺漏会显示具体提示，邮编可以辅助选择马来西亚州属，顾客仍可手动确认。默认跟单小狗是毛毛，可自选其他店员。八只小狗有不同的合成叫声。

下单后会保存号码牌。追踪局显示单个当前制作订单、待处理数量、我的小狗和两组公开队列。输入订单号或电话后四位会同时搜索，多个结果需要顾客选取。找到后固定在我的小狗里，同一浏览器下次回来仍可查看。查看物流必须再核对电话后四位。已领取员工证的麻瓜，在其他浏览器核实订单并重新领取后，会找回同一个员工号。

订单阶段由店长更新。在同一个阶段内，狗的表情以进入该阶段的时间为起点，每满 24 小时切换一个。它不会自动改变订单的真实阶段。

麻瓜来信提供第一人称投信动画、公开信封、补充说明、留言、店长回复、许愿人标识和敲木鱼。没有水池。每个访客每天可敲三次，马来西亚时间午夜重置。未核实身份时以浏览器访客计，领取员工证后以已核实下单电话计。完全清除浏览器数据的匿名访客无法被可靠识别为同一个自然人。

## 员工证

下单后自动入职，工号取同一下单电话对应的最早订单号并永久保留。旧浏览器的订单也会补上员工证。元老章盖在头像旁边，身份显示在名字下面。追踪局、信封和有身份留言显示同一身份。

| 徽章 | 条件 |
| --- | --- |
| 入职麻瓜 | 第一次下单 |
| 开所元老 | 工号 #001–#200 |
| 话唠麻瓜 | 留言满 10 次 |
| 回头麻瓜 | 下单满 3 次 |
| 见过店长 | 面交过一次 |
| 耐心麻瓜 | 收到过预购商品 |
| 信被拆啦 | 一个点子被实现 |
| 收集麻瓜 | 买过 3 款不同产品 |
| 功德麻瓜 | 累积敲木鱼 10 次 |

元老为永久纪念章，不计入升级。其余徽章解锁 1 / 3 / 5 / 7 个，对应实习麻瓜 / 麻瓜员工 / 资深麻瓜 / 麻瓜主管。徽章解锁后保留。点子被实现时，店长在后台点「实现点子，拆信盖章」，公开状态与徽章会一起更新。

## 新订单和状态通知

`notify.mjs` 每分钟处理待发送通知。邮件和 WhatsApp 需要各自配置。

新订单邮件使用 Resend。在环境变量中填写 `RESEND_API_KEY`、接收地址 `SHOP_EMAIL` 和已验证发件地址 `EMAIL_FROM`。

WhatsApp 使用 Meta WhatsApp Business Cloud API。填写 `WA_ACCESS_TOKEN`、`WA_PHONE_NUMBER_ID`、当前支持的 `WA_API_VERSION`、已批准模板名称 `WA_TEMPLATE_NAME` 和模板语言 `WA_TEMPLATE_LANGUAGE`。模板正文使用三个按顺序排列的变量，分别为订单号码、订单状态、运单号。模板示意为 `麻瓜你好，订单 {{1}} 已更新为 {{2}}。物流资料 {{3}}。`，实际模板须在自己的账号中提交并获批。顾客勾选接收进度后，店长改变状态才会排入 WhatsApp 发送。

配置为空时，后台显示待配置。真实发送成功后显示已发送，收到错误后可以人工重试。网络中断导致结果不确定时标成待店长核对，避免自动反复发送同一通知。邮件使用唯一幂等键。第三方邮件和 WhatsApp 服务可能产生费用，由账号服务商计算。

店长也可在后台开启浏览器桌面提醒。页面保持打开并获得浏览器许可时，检测到新订单会提示。关闭网页后的邮件推送由邮件服务与收件设备设置控制。

本次交付没有连接店长的外部数据库、发件邮箱、Meta 账号或 Netlify 账号，未执行真实发送。可先独立测试商店，再按需配置通知。

## 校验

运行 `npm install` 后，执行 `npm test` 可检查订单重试、规格库存、状态、徽章和身份隔离。手机尺寸的顾客下单、查单验证、领取员工证、留言、投信、木鱼，以及后台编辑商品和订单，已通过本地浏览器操作检查。仍需在自己的正式域名和数据库上完成部署后的真实核对。

## 字体、图案与声音

页面以参考截图的厚实、圆润感觉搭配 Noto Sans SC、Baloo 2 和站酷快乐体。截图没有原字体文件，因此并非识别并复制了参考网站的确切字体。字体许可见 `public/*OFL.txt`。

插画为本次设计生成的手绘素材。小狗表情为同一角色上的眼睛、嘴形、眼泪及道具变化。狗叫、纸张投递和背景小曲为合成音效，木鱼与圣杯使用项目内音频。小狗说话可在支持中文语音的浏览器朗读，同时保留对白文字。音效和音乐各有独立开关。

## v7 已确认的互动规则

- 订单状态：待核款 → 排队中 → 制作中 → 待寄出 → 已寄出 → 已完成；面交分支为「要面交」，未收到款可由店长改为「不等咯」。保留旧状态 ID，历史订单不会被错误改状态。
- 每个状态三句店长文案，以订单、状态进入日、马来西亚当天日期确定。同一天刷新保持不变，每过马来西亚午夜换一句。
- 小狗表情从当前状态进入日开始，每过当地午夜推进一档，停在最后一档。问号眼／沙漏、八字眉弯眼→无神无语→瞌睡、敲木鱼→冷汗→灵魂出窍、放大镜验货、水汪汪期待、开怀笑、毕业帽笑、虚线「离家中」配两团烟。
- 点狗头会压扁狗头，并按当前表情播放音效：犬吠、提示、呼噜、叹气、木鱼或退场音。声音使用浏览器合成，木鱼使用本地音频；总音效开关统一控制。
- 结账可选捎话：催店长／佛系等单／给店长打气／嘴硬，也可自写或留空。只有有捎话的订单显示上方讲话框；其他文案在名字下方。修改捎话须验证下单电话后四位。
- 完整员工证须验证订单和电话后四位；公开档案只展示职位、工号、徽章等公开资料，不展示真实姓名或电话。证件带跟单小狗、装饰条码和方形开所元老章。条码是视觉元素，不用于付款或门禁。
- 商品分类为双列图卡；点分类进入当前分类，支持价格／名字排序及现货／预购／定制筛选，点外部或返回按钮退出。购物车可清空。
- 表单输入框失焦会提示错误。邮编匹配城市及州属，均可手动修改。付款只突出应付金额，复制后显示成功提示。
- 麻瓜历每日宜忌按马来西亚日期变化，红绿圆章；底部导航使用下划线选中反馈。
- 本地 HTML 和 Netlify Drop ZIP 都是本机存储演示。多人共享订单、店长登录、邮件、WhatsApp 通知仍需完整项目及环境变量，不会因上传静态演示而自动启用。

## v9 多订单跟单与界面

- 首页不显示顶部固定栏，店铺／追踪／来信页继续固定。首页入口图文居中，讲话框尾巴指向小狗头；信箱旁的小狗留守，点击整个信箱即可写信，移除重复的写信按钮。

- 同一麻瓜的「我的小狗」合并：跟单小狗沿用第一笔订单选择；显示可点击的全部订单号码，汇总商品数量。点号码可看对应公开订单详情；已寄出订单显示各自包裹按钮，物流依然核对电话后四位。员工证与捎话入口只出现一次且同样式。
